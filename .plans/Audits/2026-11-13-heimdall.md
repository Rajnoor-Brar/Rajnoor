# Audit: Heimdall, for the projects page

**Audited:** 2026-11-13, `~/Github/Heimdall` at `main`, 249 commits, last commit 2026-11-11
**Repo:** <https://github.com/Rajnoor-Brar/Heimdall> (public, GPL-3.0, no GitHub description)
**Goal:** decide whether and how Heimdall goes on rajnoor.in/projects, and what the page may claim.

## Verdict

Put it on the site. It is the strongest engineering artefact the portfolio has: a coherent design, made explicit and defended in writing, with a test suite and docs at a scale few student projects have. The page should sell the **design ideas** (tools as processes, identity-based reruns, partial-named products, refuse-early checks), not line counts, and must not claim the system is portable or finished. On this Mac the fast test suite does not run as checked in (two defects, below). Brookhaven is the study that shows it working, so the two pages should link to each other.

## What it is (verified)

- **Purpose.** A runner for Monte Carlo studies in high-energy physics. A TOML "errand" file declares a chain of tools (Pythia, Herwig, Sherpa, Whizard, MadGraph, Rivet, Delphes, user programs). Each tool is its own OS process, connected to the next by FIFOs, and the runner plans, supervises, records and plots. Source: `README.md`, `docs/stable/start/model.md`.
- **Size** (tracked files, `editor/` excluded): Python 34.7k lines in `framework/`, 26.5k in `tests/`; C++ 3.5k in `src/` (the ROOT plotting app `Paint`, the Pythia driver, a YODA→ROOT converter); 2.2k in `recipes/` (the stack builder). 8.6k lines of Markdown docs.
- **Tests.** 108 Python test files, 1,441 test functions, which expand to 2,421 collected cases (31 marked `slow`), plus 4 C++ test programs.
- **Surface.** 13 tool folders in `framework/tools/`; 41 subcommands in `docs/reference/commands.md`; a generated settings reference; `heimdall docs` builds one searchable HTML page from all of it.
- **History.** v0 was a hand-built C++ `utils/` (10.4k lines). v1 was a Python orchestrator (17k lines, 19 commands) over an in-process C++ event loop. v2/Heimdall was rewritten to process-per-tool, then split from `High-Energy` into its own repository (`docs/stable/design/history.md`). The hidden **Lambda** stub on this site (`content/projects/lambda/`, "Probe / Record / Monitor / Paint") describes that v0/v1 lineage.
- **Cadence.** 249 commits between 2026-10-10 and 2026-11-11, most of them in two bursts (Oct 26 – Nov 2 and Nov 7 – Nov 11).
- **Process.** `AGENTS.md` and `docs/rules/work.md` define a planned pipeline (audit/spec → design plan → agent implementation round → review → close). `.plans/Issues.md` holds about 60 triaged issues, each with cause, user impact and a done-when.

## What is worth showing (non-obvious)

1. **Failure semantics designed in, not patched on.** FIFO chains deadlock when a writer dies before opening its pipe, and a reader sees end-of-file as success when the generator crashes mid-stream. `framework/runner/execute.py:1-40` handles both by construction: each tool gets its own process group, the first nonzero exit is the cause, a SIGPIPE death is never blamed, the consumer's event count is checked against the producer's sidecar, and products keep a `.partial` name until every check passes, with `.complete` written last. This is the most defensible engineering on the page.
2. **Identity-based reruns.** A rerun of an unchanged study does nothing, and a changed one reruns exactly the points whose identity changed. A golden file pins the identity (`tests/runner/test_identity_golden.py`).
3. **Physics stays in native cards.** TOML carries only wiring and sweeps, and each tool merges an override by its own rule (Pythia: the last line wins; Sherpa: deep merge). This sidesteps the usual "one config dialect for every generator" trap. The cost is stated too: matching knobs across generators is manual (`docs/stable/design/principles.md`).
4. **Principles with their costs written down.** `principles.md` gives each principle "Buys / Costs", including a measured 0.90× throughput cost of the process model. `refused.md` lists what the design refuses to do. That is uncommon and worth quoting.
5. **A ranking engine with an audit trail.** `framework/stats/` (2.7k lines) scores every curve against data on eleven metrics in categories, ranks points, and computes stratum-matched "marginals". Every summary prints how its numbers were made.

## Real problems (by impact)

1. **The fast suite does not run on macOS as checked in.** Two independent defects:
   - `tests/runner/test_runs.py` calls `os.stat("/proc/1")` inside a `skipif` at import time. macOS has no `/proc`, so collection raises `FileNotFoundError` and pytest aborts the session before running anything (`Interrupted: 1 error during collection`). Fix: guard with `Path("/proc/1").exists()` first, or move the check into the test body.
   - An untracked, generated PLY parser table `py.py` (16 KB, `_tabversion = '3.2'`, apparently left by MadGraph's UFO parser) sits in the repo root. `python3 -m pytest`, which is exactly what `make test` runs, puts the cwd on `sys.path`, so `import py` loads this file and pytest dies with `AttributeError: module 'py' has no attribute 'path'`. Fix: delete or move it, and add `py.py` / `parsetab.py` to `.gitignore`.

   - With both worked around, `test_detach.py::test_stop_finds_one_of_your_runs_and_waits_for_it` hangs indefinitely on macOS: `heimdall stop --pid` waits for a run's end and never returns. Not diagnosed. The likely cause is the same Linux assumption: `runner/runs.py:227-230` (`started_at`) and `:428` read `/proc/<pid>/stat`, and `events.py:350` reads `/proc/net/unix`. A test that can hang also needs a timeout (`pytest-timeout`, or `proc.wait(10)` placed before the `cli.main` call can block).

   Together these mean `make test` fails on the developer's own platform, while `docs/stable/setup/platforms.md` and `recipes/platforms/mac/` present macOS as supported. The only CI (`.github/workflows/stack.yml`) is manual-dispatch on Ubuntu, so nothing catches a platform regression.
2. **No automatic CI.** The suite is large, but it runs only when someone runs it. A cheap `on: push` job running the stack-free subset (pure-Python tests that skip without the stack) would catch defects like the two above. Issue I-13 (no ruff, mypy or `pyproject.toml`) is still open.
3. **This machine's environment is mid-migration.** `~/Himinbjorg` does not exist; the stack is still at `$HEIMDALL/stack` and `$HEIMDALL/forge` (gitignored). `gjallarhorn.sh` refuses to load and asks for `python3 recipes/machine.py adopt`. Not a code bug, but no screenshot or demo run for the page can come from this Mac until the adopt is done. *Not run by me: it moves files.*
4. **Docs contradict the code in two places**, which matters because the project's own rule is "a contradiction is a finding":
   - `docs/stable/design/refused.md` lists "Built-in statistics and fits" as refused (V4), yet `framework/stats/` is a 2.7k-line built-in scoring and ranking engine with its own CLI (`heimdall rank`). Either narrow the row to "fits" or record the reversal as a decision.
   - `principles.md` says "Small by surface area … (v1 had 19 commands)". `commands.md` lists 41 subcommands, and at least three of them (`stats`, `score`, `deck`) only refuse with a pointer to the new name. I-26 tracks the refusal stubs, but the principle as written is no longer true.
5. **Licensing of `editor/` assets.** `editor/heimdall-icons/` ships 1,258 SVGs its own `package.json` calls "Material-derived" under MIT, with no upstream copyright notice; MIT requires the notice. `editor/icon-bank/` holds 9 Vecteezy files (Vecteezy's free license requires attribution and does not allow redistributing the files as such), plus svgrepo icons and the ROOT and Pythia logos (trademarks). They sit in a public GPL-3.0 repository. Low effort to fix: add the upstream notices, or move `icon-bank/` out of the public repo.
6. **Committed binaries.** Three `.vsix` packages are in git (`editor/*/*.vsix`). They are rebuildable from source, so release them or drop them.

## Questionable decisions

- **The one-month build rate against the maturity claim.** 249 commits in a month, a ~60-issue backlog, "Next pieces" still P1, two docs tests known red until a crystallise (I-152), and a v2→v3 config dialect migration not yet done (I-20, I-21). The page must call this **active, pre-release research software**. Calling it a finished framework would be refuted by a visitor's first look at `.plans/Issues.md`.
- **The process-per-tool cost is real but stated.** The 0.90× throughput figure is stated honestly. No change is needed; quote it rather than hide it.
- **Ranking defaults can mislead.** I-157 (open, P1) says that with gates off by default, a broken point's noise can make a real effect read as "indistinguishable from the best" in the marginals. Brookhaven's report used those defaults. The Brookhaven page must not lean on marginal "≈ best" verdicts without that caveat (see the Brookhaven audit).
